# Unpredictable Bench

**An LLM benchmark you cannot prepare for.**

Tasks are generated from a random seed *at run time* and never published. Training on the benchmark is physically impossible — the evaluation set does not exist until the run happens.

**Site:** https://pyfile-toolkit.github.io/unpredictable-bench/

## Why

Static benchmarks leak. Their questions live on GitHub, arXiv and Stack Overflow for years, so models memorize them and reported scores stop measuring capability. LiveBench rotates questions monthly, but even a monthly set can be partly memorized.

This benchmark removes the attack surface entirely:

- **Task from a seed** — 225 worlds deterministically generate tasks from a seed. Nothing is stored in advance.
- **Never published** — reports contain aggregates only. No individual question is revealed.
- **commit-reveal** — `sha256(seed)` is published *before* the run, the seed *after*. This proves the set was not swapped.
- **Contamination gap** — old tasks are mixed back in; the fresh-vs-old gap directly measures memorization.

## Contamination gap

A task depends on the seed, and a solver must solve it for any seed. So tasks from a previous run can be regenerated byte-for-byte (from a `ref`) and mixed into the current set:

| candidate | fresh | old | gap | verdict |
|---|---|---|---|---|
| honest solver | 100% | 100% | **+0.0 pp** | solves |
| memorizer | 0% | 100% | **+100.0 pp** | recalls |

`gap > 15 pp` is a reliable sign a model is optimized for the benchmark rather than solving it.

## Contents

- **225 task worlds** across math, algorithms, graphs, SQL, compilers, OS, crypto, physics, chemistry, biology, geography, linguistics, economics, finance, logistics, marketing, medicine, law, games, puzzles, probability, electronics, music, cooking, sports and more.
- **Three checker kinds:** formal (compare to reference), differential (answer is code, executed on random inputs against a reference), and open (no reference — routed to human A/B voting).
- **IRT calibration:** a Rasch model yields a candidate θ comparable across rounds even when task sets differ.

## Run it

```bash
# reference solver (our own deterministic code, 0 LLM calls)
node scripts/bench/run.mjs --candidate=script:all

# a real model via a provider API (direct, not through any proxy)
node scripts/bench/run.mjs --seed=myrun --candidates=direct:groq:openai/gpt-oss-120b

# framework self-tests
node scripts/bench/test.mjs
```

Specs: `script:*` (code solver), `llm:*` (freellmapi), `direct:provider:model` (provider API), `interactive:stdin|file`, `self`.

## Status

Early. The framework, 225 worlds, IRT calibration, contamination metric and human-voting pipeline are implemented and tested (23 meta-tests pass). Real-model runs are quota-limited; contributions of provider keys for independent runs are welcome.
